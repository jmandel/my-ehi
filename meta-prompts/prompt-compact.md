# Epic EHI export → skills + deep dives

This folder starts with `raw/` — a **redacted, same-shape** Epic "EHI Export" of my records (thousands of TSVs + schema HTML + notes + messages), produced by `skills/import-ehi/` (zip → identifiers → human-reviewed terms → fuzzy-redact → prove 0 residual; run it first if handed a zip). Treat `raw/` as a read-only specimen. Mission: develop **two skills** — reading the export, building deep dives — then the dives.

**Core idea:** my export is one specimen of a genre — learn the species from the individual. Genre knowledge → skills; specimen facts → generated artifacts. Always ask: *genre, or specimen?* (The dives are the exception: tied to my real record.)

`raw/` is already redacted, so the only discipline is **portability**: specimen values stay out of skills; describe the mechanism, not the cell; audits **value-grep** for transcribed specimen values (instructions alone don't stop transcription).

**Way of working:** workflows + sub-agents are the default unit; the lead orchestrates and synthesizes — the failure mode is the lead quietly working solo. Craft: (1) a standing preamble for every agent — DB incantation + traps + house rules (*genre not specimen · method not data · explain why*); (2) artifacts to disk, returns are receipts (work survives crashes; journals resume); (3) one writer per file per phase; (4) adversarial verification before anything ships (skeptics refute claims against rows, re-run SQL, value-grep drafts). Method: **top-down × bottom-up** (discoveries live in the gap); **explain *why*, not just *what*** — chase each quirk to its mechanism.

**Stack:** bun + TypeScript end to end; SQLite substrate. The loader is **one command** building the complete DB: all TSVs **plus schema HTML parsed to catalog tables** (`_tables`, `_schema_table`, `_schema_column` — the schema made queryable: the biggest force-multiplier; never a two-step half-build). Ship `q.ts`. Traps: everything is TEXT (CAST or sorts lie); a blank column is rarely no-data (dropped `_NAME` companion / export view — check the code column); schema docs are aspirational (PRAGMA real columns).

**Skill 1 — Reading:** the method; mapping (inventory from the catalog, not `ls`; locate notes/messages/media joins); **general patterns** (CSN, `*_DATE_REAL`, master files, base+supplement, `_C_NAME`, status matrices, soft-deletes…) each chased to why with a traced example (cite concept+number; bare §refs rot on renumber); **clinical-area guides** per domain (encounters first): tables, verified joins, decoys, gotchas-to-why, tested SQL. Force: **coverage accounting** (classify every populated table: domain / new / infrastructure; the residue hides under-documented domains) and **map the negative space** (a plumbing guide: what's skippable *and why*; which plumbing-look tables are load-bearing).

**Skill 2 — Deep dives**, view-first: ideate → explore (loop) → **abstract to one clean view model** (single JSON: structured + narrative + assessment + evidence map; extract/enrich/synthesize; clean projection, never raw Clarity on screen; parts are source, assembly idempotent) → build static React/D3 on the view model alone, custom viz, screenshot-verify, HTTP serve, subpath-safe site build (DB rebuilt from `raw/` at publish). Each dive ships **BUILD.md** — the build spec that spares reverse-engineering the view model: TS interface + per-slot method from raw incl. judgment rubrics (**method, not data**; design rationale is a section here, not a second doc).

**Payoff:** pick five diverse dives only after the data work; build view-first via workflows; feed friction back into the skills. No infographics, no raw dumps. Ref: github.com/anthropics/skills → skill-creator/SKILL.md
